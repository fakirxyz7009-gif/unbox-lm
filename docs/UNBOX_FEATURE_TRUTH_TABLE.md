# Unbox Studio feature truth table

**Updated:** 2026-11-11  
**Evidence source:** [Phase 0 audit and baseline](PHASE_0_AUDIT.md). This table describes observed code paths, not marketing claims or release signoff.

| User-facing area | What is real in the current app | What it does not establish |
| --- | --- | --- |
| Audio generation | The shared Web Audio graph renders app-owned DSP, recorded sample packs and explicitly labelled proxy DSP. The legacy SoundFontEngine's built-in tabla, bansuri, sitar, guitar, piano, dhol and harmonium banks are generated by app-owned DSP; private `Custom` stem files can override selected models in the personal build. Workstation LOAD can import user-provided SF2 presets and bind their parsed sample zones to a project instrument. RV7000 can import a user-provided local impulse response or select existing project audio (including captured takes and imported clips); its decoded asset travels with project saves/archives and is copied to the offline render graph. Every stored project-audio asset now carries a bounded origin record; direct local files/SF2 are explicitly `user-file` with unknown rights until the user declares otherwise. | No inspected audio-render path asks a generative model to synthesize waveforms. Modeled buffers are algorithmic, not recordings of musicians. SF2 import maps common preset/key/velocity/sample/loop generators, instrument `scaleTuning`, initial filter cutoff, and the default velocity-to-cutoff and concave velocity-to-attenuation responses, plus volume-envelope delay, attack, hold, decay, sustain, release and key tracking for hold/decay. Loop-until-release tails and exclusive-class voice choking are supported. Custom SF2 modulators and exact SoundFont envelope contours remain unsupported or approximate. Provenance is a record, not license verification; an imported impulse response or user file remains unverified until the user supplies evidence. Private Custom stems have no verified performer/license and are excluded from the share build. |
| Linked user audio | Link import now requires a source URL, an explicit user-chosen basis (**own/direct permission**, **CC0**, or **CC BY**) and a confirmation; CC BY requires credit text. That declaration is bounded, saved with the local audio asset, and retained in version-2 `.unbox` archive metadata on export/import. | It is a user declaration, not license authentication, permission from a platform, or a grant to redistribute the audio. Users must not import commercial songs or material they lack rights to use. |
| AI features and audio | Gemini-backed features provide rack plans, device parameter suggestions and text mix notes. A regression pins the AI router to those three symbolic/text endpoints. The legacy `/api/generate-sound` route was removed because it exposed hard-coded local song-derived patch files and had no client callsite. | No inspected audio-render path asks a generative model to synthesize waveforms. AI assistance may still change symbolic device choices or parameter values. |
| Rack patching and Combiners | The real Rack UI regression adds a CC0 recorded guitar and stereo delay, measures its routed output, then uses rear-panel jack pointer events to cancel a move, replace a cable on an occupied input, and restore the stereo route. The front-facing Combiner **Macros** editor lets users name macros; map continuous numeric controls on grouped devices; set normal or inverted min/max travel; and add/remove targets and macros. An audio-clock capture measures a UI-authored Wet Mix mapping changing delayed-only output from 0 to 0.0696 RMS, and reload confirms its mapped target remains interactive. | The tested group is deterministic setup because it combines an instrument and inserted effect; the macro mapping itself is created through user UI. This does not establish every audio/CV edge case, all group-creation workflows, sound quality, native plugin hosting, or complete Reason compatibility. |
| Recorded instrument packs | Pack manifests include source, attribution and license metadata; the sample engine plays recorded audio. The workstation LOAD browser and Devices pages offer a **Recorded audio only** filter that hides modeled instruments and shows bundled sample-pack devices. The SFZ importer preserves attack/release triggers, sticky keyswitch articulations, momentary `sw_down` / `sw_up` selectors, velocity crossfade ranges/curves and live CC1 fades where a source provides those layers. The CC0 Virtuosity Drums pack is performed by drummer Austin McMahon; MIDI 96 plays its five recorded continuous-roll dynamics layers across three mic groups. Chrome loaded the shipped 92-zone pack, held 15 looped voices, measured RMS changing from 0.0032 to 0.0253 (+17.9 dB) after CC1, then confirmed key-up release and the Length control truncating the loop. A same-device 640 ms live/offline comparison measured a 3.06% RMS difference and matching 0.0108 peaks; the recorded pipe organ comparison measured a 0.36% RMS difference. The CC0 Meta Piano includes four overlapping velocity layers across MIDI 21–108; the CC0 Chemnitzer Concertina pack includes three attack layers and release-trigger samples. The CC0 Shinyguitar Archtop pack credits D. Smolken as performer and mapper and covers MIDI 40–84 with 64 sample zones. The pinned CC0 FreePats Button Accordion HN pack adds Jeff Stauffer's recorded Hohner accordion across MIDI 47–91, with sustain-looped attack samples and release triggers; Chrome verified the MIDI 47 root, sustain loop, key-up release trigger and audible sample output; its regression confirms `--keys` clipping preserves the source sample root. Redistributable packs are filtered for share builds. | Attribution does not necessarily identify a performer. Claim a named performer only when the source verifies that role. Four `Custom` packs are private and have unestablished redistribution rights. One shipped CC1 source and the measured organ/roll comparisons do not establish live/offline parity for every articulation, every pack or physical MIDI playback. |
| Local plugin library | Scanner reads metadata and playable previews. A mounted library unit uses the app's labelled Web Audio proxy DSP. | Discovery or a `hostable` flag does not load or execute the plugin binary. Native VST3 hosting is not implemented in the DAW. |
| Reason Rack ecosystem reference | The app-owned device reference is generated from this checkout and labels DSP, recorded packs, and proxy units. A separate 964-row third-party Reason Remoter snapshot records 131 developers and the directory's product categories; its reported totals were rechecked on 2026-10-28. A dated snapshot of the official Reason Studios device page records 93 listed products by its four palette categories, with some published descriptors. | Reason Remoter is a discovery index, not an audited inventory of current Shop availability or Reason-version compatibility. The official device page mixes internal devices and separately sold products without labeling every product’s format. Only rows with individual Reason Studios Shop/manual links were checked as Rack Extension evidence; no Reason Rack Extension is loadable by Unbox Studio. |
| VST3 development probe | A project-owned test delay builds and processes one-second stereo impulses at four sample-rate/block-size pairs in a standalone offline host; Steinberg validation passed 47 fixture checks. | It is not Electron integration, live transport, third-party compatibility, MIDI, automation, PDC, editor hosting, state recall or crash recovery. |
| Music separation | The **built-in separator** is the default: short-time spectral masks (held notes against drum hits by median filtering, stereo position, low frequencies) computed in a Web Worker, with the last stem as the exact remainder so the stems reconstruct the source sample-for-sample. On a synthetic test mix with known parts it put 78–92 % of each part in its own stem (the trained model: 70–100 %); real songs bleed more. An optional local Spleeter/Demucs path uses a trained source-separation model only after an explicit per-session acknowledgement in the UI; the browser and local route both reject model processing without that acknowledgement. Both paths derive from the selected source and label saved stems as derivatives. | Neither path creates a new song, performer, instrument, or verified human recording; neither grants rights to the source or its stems. The trained-model path is non-generative but may introduce bleed/artifacts, and it does not isolate arbitrary stems cleanly. |
| MIDI recording | Simulated Web MIDI events reach a selected/armed instrument and create a piano-roll note clip; note lengths follow key release even with sustain, note-offs return to the instrument that received note-on after a part change, and same-pitch notes and sustain are channel-specific. Song vs Pattern destination and the Pattern id are captured when recording begins. Browser regressions verify MIDI access is requested after explicit Connect MIDI and when recording an armed instrument; the simulated workstation path records MIDI 60 at velocity 100/127 and survives IndexedDB save/reopen. Project transitions are blocked while a take is finalizing. Physical hardware acceptance is intentionally not claimed: in the latest user-approved Impulse check, permission was allowed but neither Chrome nor Windows exposed a Novation input port, so the app had no event to record. | A simulated controller proves the app path, not the physical controller, USB driver, browser port ownership, channel configuration, audible monitoring, or more key/channel cases. Active MIDI crash recovery remains open. A physical acceptance needs a visible named/identified input port, a captured press and release in the normal workstation, and project save/reopen evidence from that same session. |
| Audio recording recovery | Armed audio inputs and master-output capture journal copied AudioWorklet blocks to IndexedDB in batches. Unpacked Windows tests restore both captures after a forced exit. A recovered master clip keeps its capture start and starts muted. | Recovery extends through the last committed batch. Portable-wrapper and physical-input crash tests remain open. |
